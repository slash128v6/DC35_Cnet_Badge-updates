DC35 Radar Badge · firmware 1.0.32

Flash from your browser

Install the badge's firmware over a USB cable, straight from Chrome or Edge. Nothing to download, and the release is checked before a byte is written.

Before you start

  • Chrome or Edge, on a computer. Firefox and Safari can't talk to USB serial ports, and neither can phones. No Chrome or Edge? Flash by cable instead.
  • A USB cable that carries data. Many charging cables only carry power, and the badge then never shows up.
  • Plug the badge in and switch it on. Close anything else that might be using it, such as the Arduino IDE's serial monitor.

What happens when you click

  1. Pick the badge from the list. The browser asks which device to use. The badge shows up as CP2102 USB to UART Bridge Controller or similar, with its COM port on Windows. Choose it and click Connect. Nothing listed? See No badge in the list.
  2. Choose Install DC35 Radar Badge.
  3. Leave “Erase device” unticked to keep the badge's name, Wi-Fi details, settings, best scores and CTF progress. Tick it only to wipe the badge completely, before passing it on.
  4. Click Next, then Install, and wait about a minute. Don't unplug it while the bar is moving.
  5. Close the dialog. The badge restarts into the new firmware; the version shows at the top of Settings.

If it says it can't connect, hold the badge's BOOT button down while it tries, then let go once it starts writing. A different cable or USB port fixes most of the rest.

No badge in the list

The badge's ESP32 board talks to the computer through a USB-to-serial chip, and the computer needs that chip's driver. The badges use a Silicon Labs CP210x chip; some other ESP32 boards use a WCH CH340 instead. Check the cable first, then:

Windows

Open Device Manager with the badge plugged in. Under Ports (COM & LPT) it should appear as Silicon Labs CP210x USB to UART Bridge (COM…). If it isn't there, or appears under Other devices with a yellow warning sign, install the driver:

  • CP210x: the CP210x Universal Windows Driver from Silicon Labs. Unzip it, right-click silabser.inf and choose Install.
  • CH340: CH341SER.EXE from WCH, then Install.

Unplug the badge, plug it back in, and reload this page.

macOS

Recent macOS usually needs nothing. If the badge doesn't appear, install the macOS driver from the same Silicon Labs page, then allow it in System Settings → Privacy & Security when asked, and plug the badge in again.

Linux

The driver is built in. If the badge is listed but won't connect, your user probably isn't allowed to open serial ports: add yourself to the dialout group (uucp on Arch), then log out and back in.

What is checked, and what is written

The page reads the release published beside it and checks the signature on its manifest against the public keys built into every badge. It then checks the firmware's size and SHA-256 against the signed manifest. A badge updating over Wi-Fi makes exactly these checks, so a release it would refuse is refused here too.

The bootloader, partition table and OTA selector come from the same release build but aren't covered by the signature. They're what any ESP32 Arduino build of this badge writes, and the badge never updates them over Wi-Fi.

AddressFileWhy
0x1000flash/bootloader.binstarts the chip
0x8000flash/partitions.binlays out the flash: two firmware slots, settings
0xE000flash/boot_app0.binpoints the badge at the slot being written; without it, a badge that has updated over Wi-Fi keeps booting the old one
0x10000cnet-badge-1.0.32.binthe firmware

Settings live at 0x9000 and are left alone unless you tick “Erase device”.
